# cPanel mail and administrator user deletion

This release adds a per-staff SMTP/IMAP mailbox. It does not create cPanel mailboxes or change their passwords. Existing internal messages remain under **Previous staff messages**. SMTP sends both staff-to-staff and customer email through the actual company mailbox.

## Deployment order

1. In Supabase SQL Editor, apply `supabase/mail-v7.sql` **after** both v6 migrations. Keep older migrations out of subsequent deployments; they replace permissions and trigger definitions. The new migration is rerunnable and retains financial and operational history.
2. In Netlify, set the server environment variables listed in `.env.mail.example`. `SUPABASE_SERVICE_ROLE_KEY` must stay in server configuration. Never copy it, encryption keys, VAPID private keys, or mailbox passwords into `www/config.js`, GitHub, screenshots, or chat.
3. Obtain the exact secure hostname from **cPanel → Email Accounts → Connect Devices → Secure SSL/TLS Settings**. Set it as `MAIL_IMAP_HOST` and `MAIL_SMTP_HOST`. Use IMAP 993 and SMTP 465, or SMTP 587 with mandatory STARTTLS. TLS certificate verification remains enabled. Set `MAIL_ALLOWED_DOMAINS` to your company domain(s), separated by commas. Do not guess `mail.<domain>` if cPanel specifies a different certificate hostname. [Namecheap cPanel mail settings](https://www.namecheap.com/support/knowledgebase/article.aspx/9142/2186/general-configuration-for-mail-clients-and-mobile-devices/), [cPanel Connect Devices](https://docs.cpanel.net/cpanel/email/set-up-mail-client/).
4. Generate a 32-byte encryption key and a Web Push VAPID key pair using the commands in `.env.mail.example`; save the private values directly in Netlify. Preserve the encryption key securely: replacing it requires reconnecting every mailbox. VAPID rotation requires staff to enable notifications again.
5. Merge and deploy the release to the existing Netlify site. Build command remains `node scripts/stamp-web-release.mjs`, publish directory `www`, functions directory `netlify/functions`. No additional hosting provider is required. The mailbox endpoint and scheduled poll require Netlify Functions with outbound TCP/TLS access to the cPanel server. Static-only GitHub Pages cannot run mail. Capacitor/TWA builds must point at the hosted endpoint; see the note below.
6. Each staff member opens **Mail → Mailbox settings**, enters their existing company email and **mailbox password**, then chooses **Connect mailbox**. Both IMAP login and SMTP authentication are verified before encrypted credentials are saved. One mailbox is assigned to one staff ID. A password change in cPanel requires updating it here.
7. Staff choose the bell icon in Mail and allow browser notifications on each device. Verify that the Netlify `mail-poll` schedule is active after production deployment; scheduled functions do not run on deploy previews. [Netlify scheduled functions](https://docs.netlify.com/build/functions/scheduled-functions/).

## What is included

- Gmail-style responsive folders, search, pagination, unread markers, stars, reading, To/CC/BCC, reply/reply-all, forwarding text, server-saved drafts, attachments, archive, trash and restore. Plain text is shown safely; email HTML/scripts and remote tracking images are never injected into the app.
- Sent messages are appended to the IMAP Sent folder. A failed sent-copy append is reported separately from SMTP acceptance, so it never triggers a blind resend. SMTP acceptance does not prove final recipient delivery; check bounces in Inbox.
- Sending uses a durable request ID. A timeout or uncertain SMTP outcome displays an explicit unconfirmed state. Check Sent/cPanel before manually creating another send. Do not delete delivery reservations to retry blindly.
- Message size limit: 15 MB for reading; attachments: 3 MB total on send, 3 MB per download, maximum 10 attachments/30 recipients. Larger messages and downloads can be opened in cPanel webmail. Forwarding includes the text; attachments must be downloaded and attached explicitly. Drafts are stored in the app, with explicit Save draft; attachments are selected again when sending.
- The app checks mail about every 30 seconds while visible. Browser push checks about every 2 minutes using the production scheduled function; delivery depends on network, browser/OS support and permission. Connecting the mailbox establishes a baseline without alerting on old mail. Generic notification text protects customer content on lock screens. Device identity is cleared on logout, with local push unsubscribe and server subscription removal. A disabled/deleted user or revoked mail permission stops future scheduled sends.
- Scheduled polling handles at most 20 mailboxes per run, oldest checked first. More than 20 connected mailboxes take additional cycles. Review schedule/runtime capacity before expanding staff volume. Monitor failed account checks in Netlify and reconnect invalid passwords. This is periodic checking, not an always-connected IMAP IDLE service.
- **Admin → Users → staff profile → Delete user** requires a reason and confirmation. It immediately disables app access, revokes permission grants, disconnects the app mailbox, removes drafts/push subscriptions, audits the action and soft-deletes Supabase Auth. The profile remains as a non-reactivatable audit tombstone so invoices, shipments and staff messages retain their references. Self-deletion and removing the last active admin are refused. Auth cleanup failure is visible in **Deleted users → Retry Auth cleanup**. [Supabase Auth soft-delete](https://supabase.com/docs/reference/javascript/auth-admin-deleteuser).
- Deleting an app user does not delete their actual cPanel mailbox or rotate its password. To terminate direct webmail/device access as well, the company administrator must disable that mailbox or change its password in cPanel.

## Release acceptance with real mailboxes (still required)

Use two staff test mailboxes and a customer address you control. Connect both, send staff-to-staff and staff-to-customer, then send an external reply. Check Inbox, Sent copy, replies, CC/BCC privacy, attachment integrity, search, unread/star/archive/trash/restore and drafts. Confirm new-email badge and toast while open, push with the app closed, no old-message alert on first connection, and no notifications after logout. Test at desktop and 390px phone width. Check both English and Kiswahili.

Check SPF/DKIM and deliverability in cPanel with your mail administrator; these are existing domain settings, not changed by this code. Confirm disabled-user refusal using a previously issued session as well as fresh login. Delete only a disposable staff account and confirm its historical record remains linked and Auth cleanup completed.

Local database and mocked transport/browser tests cannot verify live Namecheap credentials, DNS/SPF/DKIM, actual SMTP delivery, hosted Supabase Auth, deployment configuration or OS push delivery.

## Android hosting

The TWA uses the hosted website, so the same-origin function endpoint works after deployment. The legacy bundled Capacitor app uses its local origin and cannot call a relative Netlify endpoint; use the live TWA for this mailbox release. Native background push for a bundled Capacitor build requires a separate native push integration and is not implemented here. Web push availability on iOS requires an installed home-screen web app on a supported OS/browser. Do not claim physical-device notification behavior without the checks above.
